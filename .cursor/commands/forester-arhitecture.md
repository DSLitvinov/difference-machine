# Архитектура Forester

Forester - это гибридная система контроля версий (VCS) для 3D-моделей и кода, написанная на Go. Она сочетает в себе возможности Git-подобной системы контроля версий с специализированными функциями для работы с 3D-контентом.

## Общая архитектура

Forester использует гибридную архитектуру хранения данных:
- **Object store** — commits, trees, blobs (content-addressable storage)
- **Файловые метаданные** — refs, index, manifests, reviews, locks, stash, reflog (JSON/текст в `.DFM/`)

### Структура репозитория

```
.DFM/
├── objects/             # Content-addressable storage
│   ├── blobs/sha256/
│   ├── trees/sha256/
│   └── commits/sha256/
├── refs/                # Ссылки на коммиты
│   ├── heads/           # Ветки
│   └── tags/            # Теги
├── HEAD                 # Текущая ветка
├── index                # Staging area (JSON)
├── manifests/           # Метаданные Blender-объектов
├── reviews/             # Review комментарии и approvals
├── locks/               # Блокировки файлов
├── stash/               # Stash
├── hooks/               # Git-подобные хуки
├── logs/refs/heads/     # Reflog
└── config               # Конфигурация репозитория
```

## Основные компоненты

### 1. Storage (Object Storage)

**Файл:** `internal/core/storage.go`

Content-addressable storage для объектов (blobs, trees, commits). Использует SHA-256 хеширование для идентификации объектов.

**Ключевые функции:**
- `StoreBlob(content []byte)` - сохраняет blob с автоматическим сжатием (zlib/deflate)
- `GetBlobContent(hash string)` - получает содержимое blob с автоматической распаковкой
- `StoreTree(treeJSON string)` - сохраняет дерево файлов
- `StoreCommit(commitJSON string)` - сохраняет коммит
- `hashToPath(hash string)` - преобразует хеш в путь (ab/cdef...)

**Особенности:**
- Автоматическая дедупликация (если объект с таким хешем уже существует, не сохраняется повторно)
- Сжатие blobs для экономии места
- Валидация хешей для предотвращения path traversal

### 2. Metadata stores (filesystem)

Метаданные хранятся в файлах под `.DFM/`. См. [database.md](./database.md).

| Данные | Расположение | Файл кода |
|--------|--------------|-----------|
| Commits, trees, blobs | `.DFM/objects/` | `storage.go` |
| Ветки, теги, HEAD | `.DFM/refs/`, `HEAD` | `refs.go` |
| Staging | `.DFM/index` | `index.go` |
| Reflog | `.DFM/logs/refs/heads/` | `reflog.go` |
| Blender objects | `.DFM/manifests/` | `manifest_store.go` |
| Reviews | `.DFM/reviews/` | `review_store.go` |
| Locks | `.DFM/locks/` | `locking.go` |
| Stash | `.DFM/stash/` | `stash_store.go` |

### 3. Index (Staging Area)

**Файл:** `internal/core/index.go`

Staging area для файлов, готовых к коммиту. Хранится в `.DFM/index` в формате JSON.

**Структура:**
```json
{
  "path/to/file1": "hash1",
  "path/to/file2": "hash2"
}
```

**Ключевые функции:**
- `Add(path, hash)` - добавить файл в staging
- `Remove(path)` - удалить файл из staging
- `GetEntries()` - получить все записи
- `Clear()` - очистить staging area
- `IsEmpty()` - проверить, пуст ли staging

### 4. Refs (References)

**Файл:** `internal/core/refs.go`

Управление ссылками на коммиты (ветки, теги, HEAD). Хранятся в файловой системе в `.DFM/refs/`.

**Структура:**
- `.DFM/HEAD` - текущая ветка (формат: `ref: refs/heads/branch_name`)
- `.DFM/refs/heads/<branch>` - коммит HEAD ветки
- `.DFM/refs/tags/<tag>` - коммит тега

**Ключевые функции:**
- `SetHead(branch, commitHash)` - установить HEAD ветки
- `GetHead(branch)` - получить HEAD ветки
- `CreateBranch(name, commitHash)` - создать ветку
- `DeleteBranch(name)` - удалить ветку
- `CreateTag(name, commitHash)` - создать тег
- `GetCurrentBranch()` - получить текущую ветку
- `SetCurrentBranch(branch)` - установить текущую ветку

### 5. Hashing

**Файл:** `internal/core/hashing.go`

Функции для вычисления SHA-256 хешей.

**Ключевые функции:**
- `HashString(content string)` - хеш строки
- `HashBytes(data []byte)` - хеш байтов (для бинарных данных)
- `HashFile(filePath string)` - хеш файла (streaming для больших файлов)
- `HashTree(treeJSON string)` - хеш дерева
- `HashCombined(parts []string)` - хеш комбинированных частей

### 6. Compression

**Файл:** `internal/core/compression.go`

Сжатие данных с использованием zlib/deflate.

**Ключевые функции:**
- `Compress(data []byte)` - сжать данные
- `Decompress(compressed []byte)` - распаковать данные
- `IsCompressed(data []byte)` - проверить, сжаты ли данные

### 7. Locking

**Файл:** `internal/core/locking.go`

Система блокировки файлов для предотвращения конфликтов при совместной работе.

**Типы блокировок:**
- `LockTypeExclusive` - эксклюзивная блокировка
- `LockTypeShared` - разделяемая блокировка

**Особенности:**
- Блокировки привязаны к ветке
- Поддержка времени истечения
- Автоматическая проверка истечения

## Модели данных

### Commit

**Файл:** `internal/models/commit.go`

```go
type Commit struct {
    Hash          string     // SHA-256 хеш коммита
    ParentHash    string     // Хеш первого родительского коммита (для обратной совместимости)
    ParentHashes  []string   // Все родительские коммиты (для merge commits)
    TreeHash      string     // Хеш дерева файлов
    Author        string     // Автор
    Message       string     // Сообщение коммита
    Timestamp     int64      // Unix timestamp
    Type          CommitType // Тип коммита
    ScreenshotPath string    // Путь к скриншоту (опционально)
}
```

**Особенности:**
- `ParentHash` - первый родитель (для обратной совместимости и обычных коммитов)
- `ParentHashes` - массив всех родителей (для merge commits с несколькими родителями)
- Merge commits имеют два родителя: текущая ветка и вливаемая ветка

### Tree

**Файл:** `internal/models/tree.go`

```go
type Tree struct {
    Hash    string       // SHA-256 хеш дерева
    Entries []*TreeEntry // Записи дерева
}

type TreeEntry struct {
    Hash string // Хеш объекта (blob или tree)
    Name string // Имя файла/директории
    Type string // "blob" или "tree"
    Mode int    // Unix-style permissions
}
```

### Blob

**Файл:** `internal/models/blob.go`

```go
type Blob struct {
    Hash string // SHA-256 хеш содержимого
    Path string // Путь к файлу
    Size int64  // Размер файла
}
```

### Branch, Tag, Stash, Lock, Comment, Approval

Определены в `internal/models/commit.go` с соответствующими полями.

## Команды CLI

### Git-like команды для работы с коммитами

Forester поддерживает Git-подобные команды для работы с коммитами:

- **`add <файл>`** — добавить изменения в индекс (staging area)
- **`commit "сообщение"`** — создать коммит с указанным сообщением
- **`commit -a "сообщение"`** — автоматически добавить и закоммитить отслеживаемые файлы
- **`commit --amend "новое сообщение"`** — изменить сообщение последнего коммита
- **`commit --amend --no-edit`** — добавить новые изменения в последний коммит без изменения сообщения
- **`log`** — показать историю коммитов (подробно)
- **`log --oneline`** — краткий вывод по одному коммиту на строку
- **`log --graph --all --oneline`** — визуализация веток и коммитов
- **`log -n <number>`** / **`log --max-count=<n>`** — ограничить количество коммитов
- **`log --stat`** — статистика изменений (добавлено/удалено строк)
- **`log --name-only`** — только имена файлов
- **`log --name-status`** — имена файлов с типом изменения (A/M/D)
- **`show <хеш>`** — показать содержимое конкретного коммита
- **`show --stat`** — статистика изменений коммита
- **`show <commit>:<file>`** — показать содержимое файла из коммита
- **`reset --soft <хеш>`** — откатиться к указанному коммиту, оставив изменения в индексе
- **`reset --mixed <хеш>`** — откат + сброс индекса, но изменения остаются в рабочей директории
- **`reset --hard <хеш>`** — полный откат: удаляются и коммиты, и изменения (осторожно!)
- **`revert <хеш>`** — создать новый коммит, отменяющий изменения указанного коммита
- **`cherry-pick <хеш>`** — применить изменения из указанного коммита к текущей ветке

Все команды поддерживают короткие хеши (8+ символов), `HEAD` и `HEAD~n` для указания коммитов.

### init

**Файл:** `internal/commands/init.go`

Инициализирует новый репозиторий Forester.

**Что делает:**
1. Создает структуру директорий `.DFM/`
2. Создает ветку `main` и устанавливает HEAD
3. Создает файл `.dfmignore` с шаблоном
4. Создает директорию hooks с шаблонами хуков
5. Создает конфигурационный файл

**Использование:**
```bash
forester init [path]
```

### add

**Файл:** `internal/commands/add.go`

Добавляет файлы в staging area (index).

**Что делает:**
1. Читает файлы из рабочей директории
2. Вычисляет SHA-256 хеш каждого файла
3. Сохраняет blob в storage (с сжатием)
4. Добавляет запись в index

**Использование:**
```bash
forester add <file1> <file2> ...
forester add .  # Добавить все файлы
```

### rm

**Файл:** `internal/commands/rm.go`

Удаляет файлы из staging area и рабочей директории.

**Использование:**
```bash
forester rm <file1> <file2> ...     # Удалить файлы из индекса и с диска
forester rm -r <folder>             # Рекурсивное удаление папки
```

**Особенности:**
- Удаляет файлы как из индекса, так и с диска
- Поддержка рекурсивного удаления директорий с флагом `-r`
- Для удаления только из индекса (без удаления с диска) используйте `drop`

### drop

**Файл:** `internal/commands/drop.go`

Удаляет файлы только из staging area (индекса), оставляя их на диске.

**Использование:**
```bash
forester drop <file1> <file2> ...   # Удалить файлы только из индекса
forester drop -r <folder>           # Рекурсивно удалить папку из индекса
```

**Особенности:**
- Полезно для `.gitignore` - перестать отслеживать файлы, но оставить локально
- Требует флаг `-r` для рекурсивного удаления директорий
- Файлы остаются в рабочей директории

### mv

**Файл:** `internal/commands/mv.go`

Переименовывает или перемещает файлы/директории в индексе и рабочей директории.

**Использование:**
```bash
forester mv <old> <new>             # Переименовать/переместить файл
forester mv old_dir new_dir         # Переименовать директорию
```

**Особенности:**
- Обновляет индекс и рабочую директорию
- Поддерживает переименование и перемещение файлов и директорий

### restore

**Файл:** `internal/commands/restore.go`

Восстанавливает файлы из индекса или коммита.

**Использование:**
```bash
forester restore <file>                           # Восстановить из индекса (убрать изменения)
forester restore --staged <file>                  # Убрать из индекса (unstage)
forester restore --source=<commit> <file>         # Восстановить из коммита
```

**Особенности:**
- `restore <file>` - отменяет изменения в рабочей директории, восстанавливая из индекса
- `restore --staged <file>` - убирает файл из индекса (unstage)
- `restore --source=<commit> <file>` - восстанавливает файл из указанного коммита
- Поддержка `HEAD`, `HEAD~n` и коротких хешей в `--source`

### restore-version

**Файл:** `internal/commands/restore_version.go`

Полная перезапись рабочей директории под дерево указанного коммита (100% соответствие). Без временных папок.

**Использование:**
```bash
forester restore-version <commit>
```

**Особенности:**
- Удаляет из рабочей папки всё, чего нет в коммите (кроме `.DFM`)
- Записывает все файлы из дерева коммита в корень репозитория
- Поддержка короткого хеша и `HEAD`
- В аддоне после restore вызываются `add .`, `commit "Restore version ..."` и перезагрузка файла в Blender

### status

**Файл:** `internal/commands/status.go`

Показывает статус репозитория.

**Что показывает:**
- Текущая ветка
- HEAD коммит
- Изменения в staging area (новые, измененные, удаленные)
- Изменения не в staging (измененные, удаленные)
- Неотслеживаемые файлы

**Использование:**
```bash
forester status
forester status --color=always
forester status --no-color
```

### commit

**Файл:** `internal/commands/commit.go`

Создает коммит из staging area.

**Процесс:**
1. Проверяет, что staging area не пуста (или использует HEAD tree для `--amend`)
2. Создает tree из файлов в index
3. Сохраняет tree в storage
4. Создает commit объект
5. Вычисляет хеш коммита (SHA-256 от JSON без поля hash)
6. Сохраняет commit в object store
7. Обновляет HEAD ветки (атомарно)
8. Выполняет pre-commit и post-commit хуки
9. Очищает index

**Использование:**
```bash
forester commit "message" [--author "author"] [--tag "tag"] [--no-verify]
forester commit -a "message"              # Автоматически добавить отслеживаемые файлы
forester commit --amend "new message"     # Изменить последний коммит
forester commit --amend --no-edit         # Добавить изменения без изменения сообщения
```

**Особенности:**
- Валидация длины сообщения (MaxCommitMessageLength)
- Атомарное обновление HEAD (rollback при ошибке)
- Поддержка тегов при коммите
- Флаг `-a` автоматически добавляет измененные отслеживаемые файлы в index
- `--amend` использует parent последнего коммита как parent нового, заменяя последний коммит
- `--no-edit` при amend использует сообщение из предыдущего коммита

### switch

**Файл:** `internal/commands/switch.go`

Безопасное переключение между ветками или коммитами (заменил `checkout`).

**Что делает:**
1. Проверяет наличие ветки/коммита
2. Проверяет наличие незакоммиченных изменений (безопасное переключение)
3. Выполняет pre-checkout хук
4. Обновляет HEAD и текущую ветку
5. Восстанавливает файлы из целевого коммита
6. Выполняет post-checkout хук

**Использование:**
```bash
forester switch <branch>              # Переключиться на ветку
forester switch <commit-hash>         # Переключиться на коммит (detached HEAD)
forester switch -a <branch>           # Переключиться с автоматическим stash
forester switch -a <commit-hash>      # Переключиться на коммит с auto-stash
```

**Опции:**
- `-a` / `--auto-stash` - автоматически создает stash при переключении, восстанавливает при возврате
- Поддержка стека auto-stash для множественных переключений на одной ветке

**Особенности:**
- Безопасное переключение: проверяет наличие незакоммиченных изменений
- Поддержка detached HEAD (переключение на конкретный коммит)
- Auto-stash: автоматическое сохранение и восстановление изменений
- Стек auto-stash: при переключении между коммитами на одной ветке создается стек stash
- Выполняет pre-checkout и post-checkout хуки
- Поддержка `HEAD`, `HEAD~n` и коротких хешей

### branch

**Файл:** `internal/commands/branch.go`

Управление ветками.

**Использование:**
```bash
forester branch                    # Список веток (текущая выделена *)
forester branch -v                 # Список веток с последним коммитом
forester branch <name>             # Создать ветку
forester branch -d <name>          # Удалить ветку
forester branch -m <old> <new>     # Переименовать ветку
```

**Опции:**
- `-v` - показать последний коммит каждой ветки
- `-m <old> <new>` - переименовать ветку

**Особенности:**
- Текущая ветка выделяется символом `*`
- `-v` показывает короткий хеш и сообщение последнего коммита
- Переименование обновляет ветку в базе данных и refs

### tag

**Файл:** `internal/commands/tag.go`

Управление тегами.

**Использование:**
```bash
forester tag                    # Список тегов
forester tag <name>             # Создать тег
forester tag <name> -m "msg"    # Создать тег с сообщением
forester tag --delete <name>    # Удалить тег
```

### log

**Файл:** `internal/commands/log.go`

Показывает историю коммитов.

**Использование:**
```bash
forester log [branch]                    # Подробный вывод истории
forester log --oneline                   # Краткий вывод (хеш + сообщение)
forester log --graph --all --oneline     # Визуализация всех веток
forester log --all                       # Показать коммиты всех веток
forester log -n <number>                 # Ограничить количество коммитов
forester log --max-count=<n>             # Ограничить количество коммитов
forester log --stat                      # Статистика изменений
forester log --name-only                 # Только имена файлов
forester log --name-status               # Имена файлов с типом изменения
```

**Опции:**
- `--oneline` - краткий вывод: один коммит на строку (короткий хеш + сообщение)
- `--graph` - визуализация веток с использованием символов `*`, `|`, `/`, `\`
- `--all` - показать коммиты всех веток (сортировка по времени)
- `-n <number>` / `--max-count=<n>` - ограничить количество выводимых коммитов
- `--stat` - показать статистику изменений (добавлено/удалено строк для каждого файла)
- `--name-only` - показать только имена измененных файлов
- `--name-status` - показать имена файлов с типом изменения (A=добавлен, M=изменен, D=удален)

### show

**Файл:** `internal/commands/show.go`

Показывает детали коммита.

**Использование:**
```bash
forester show <commit-hash>              # Показать детали коммита
forester show HEAD                      # Показать текущий коммит
forester show HEAD~1                    # Показать предыдущий коммит
forester show <short-hash>              # Поддержка коротких хешей (8+ символов)
forester show --stat <commit>           # Статистика изменений коммита
forester show <commit>:<file>           # Показать содержимое файла из коммита
```

**Опции:**
- `--stat` - показать статистику изменений (добавлено/удалено строк)

**Особенности:**
- Поддержка полных (64 символа) и коротких (8+ символов) хешей
- Поддержка `HEAD` и `HEAD~n` для указания коммитов
- `show <commit>:<file>` - показывает содержимое конкретного файла из указанного коммита
- `--stat` показывает статистику изменений для каждого файла

### stash

**Файл:** `internal/commands/stash.go`

Управление стэшами (временное сохранение изменений).

**Использование:**
```bash
forester stash list              # Список стэшей
forester stash save [message]    # Сохранить изменения
forester stash apply [hash]      # Применить стэш
forester stash pop [hash]        # Применить и удалить
forester stash drop <hash>       # Удалить стэш
forester stash show [hash]       # Показать содержимое стэша
forester stash clear             # Удалить все стэши
forester stash branch <name> [hash]  # Создать ветку из стэша
```

**Опции:**

### merge

**Файл:** `internal/commands/merge.go`

Сливает ветку в текущую ветку.

**Основные опции:**
- `merge <branch>` - обычное слияние (fast-forward если возможно, иначе merge commit)
- `merge --no-ff <branch>` - принудительно создать merge commit даже при fast-forward
- `merge --ff-only <branch>` - выполнить merge только если возможен fast-forward, иначе ошибка
- `merge --squash <branch>` - объединить все коммиты ветки в один коммит без merge commit
- `merge --no-commit <branch>` - выполнить merge, но не создавать коммит (оставить в индексе)
- `merge --abort` - отменить слияние и восстановить состояние до merge
- `merge --continue` - продолжить merge после разрешения конфликтов

**Стратегии слияния:**
- `-s ours` / `--strategy=ours` - игнорировать все изменения из другой ветки (оставить текущую)
- `-s theirs` / `--strategy=theirs` - принять все изменения из другой ветки
- `-s ort` / `--strategy=ort` - стратегия ort (по умолчанию, рекурсивное слияние)
- `-s recursive` / `--strategy=recursive` - стратегия recursive (аналог ort)

**Опции стратегий:**
- `-X ours` / `--strategy-option=ours` - при конфликтах выбирать текущую ветку
- `-X theirs` / `--strategy-option=theirs` - при конфликтах выбирать вливаемую ветку

**Процесс:**
1. Проверяет, что ветка существует и отличается от текущей
2. Находит общий предок (merge base) между текущей веткой и целевой
3. Определяет, возможен ли fast-forward merge:
   - Если да и не указан `--no-ff`: просто обновляет HEAD на целевую ветку
   - Если нет или указан `--no-ff`: создает merge commit
4. Для merge commit:
   - Вычисляет изменения между merge base и обеими ветками
   - Объединяет изменения:
     - Файлы только в одной ветке → берутся из этой ветки
     - Файлы изменены в одной ветке → берутся из измененной
     - Файлы изменены в обеих ветках → конфликт
   - При конфликтах:
     - Если указана опция `-X ours/theirs`: автоматически разрешает в пользу указанной стороны
     - Иначе: помечает файл маркерами конфликта (`<<<<<<<`, `=======`, `>>>>>>>`)
     - Сохраняет состояние merge в `.DFM/MERGE_HEAD`
     - Останавливается с ошибкой, требует `merge --continue` после разрешения
5. Создает merge commit с двумя родителями (текущая ветка и целевая ветка)
6. Обновляет HEAD текущей ветки

**Множественные родители:**
- Merge commit хранит оба родителя в таблице `commit_parents`
- Первый родитель - текущая ветка (для обратной совместимости также в `parent_hash`)
- Второй родитель - вливаемая ветка
- Функции обхода истории учитывают все родители

**Обнаружение конфликтов:**
- Конфликт возникает, когда один и тот же файл изменен в обеих ветках по-разному
- Файлы с конфликтами помечаются маркерами:
  ```
  <<<<<<< HEAD
  содержимое из текущей ветки
  =======
  содержимое из вливаемой ветки
  >>>>>>> merged branch
  ```
- После разрешения конфликтов нужно:
  1. Отредактировать файлы, убрав маркеры
  2. Добавить файлы в индекс (`add`)
  3. Выполнить `merge --continue`

**Использование:**
```bash
forester merge feature              # Обычное слияние
forester merge --no-ff feature    # Принудительный merge commit
forester merge --ff-only feature   # Только fast-forward
forester merge --squash feature    # Объединить в один коммит
forester merge --no-commit feature  # Подготовить merge без коммита
forester merge --abort              # Отменить merge
forester merge --continue           # Продолжить после разрешения конфликтов
forester merge -s ours feature      # Игнорировать изменения из feature
forester merge -X theirs feature    # При конфликтах брать из feature
```

**Особенности:**
- Поддержка fast-forward merge (автоматически, если возможно)
- Обнаружение и маркировка конфликтов
- Множественные родители в merge commit
- Сохранение состояния merge для `--continue`
- Выполняет pre-commit и post-commit хуки
- Поддержка стратегий и опций разрешения конфликтов

## Процесс работы

### Создание коммита

1. **add** - файлы добавляются в staging area
   - Файл читается, вычисляется хеш
   - Blob сохраняется в storage (сжатый)
   - Запись добавляется в index

2. **commit** - создается коммит
   - Из index создается tree
   - Tree сохраняется в storage
   - Создается commit объект
   - Вычисляется хеш коммита
   - Commit сохраняется в object store
   - Обновляется HEAD ветки
   - Index очищается

3. **commit -a** - автоматически добавить отслеживаемые файлы
   - Получает tree из HEAD
   - Находит отслеживаемые файлы, которые были изменены
   - Автоматически добавляет их в index
   - Затем создает коммит как обычно

4. **commit --amend** - изменение последнего коммита
   - Получает текущий HEAD коммит
   - Использует его parent как parent нового коммита
   - Если `--no-edit`, использует сообщение из HEAD
   - Создает новый коммит с новым хешем
   - Обновляет HEAD на новый коммит
   - Старый коммит остается в истории (становится недостижимым)

### Работа с историей коммитов

1. **reset** - откат к указанному коммиту
   - `--soft`: только обновляет HEAD, изменения остаются в index
   - `--mixed`: обновляет HEAD и очищает index, изменения остаются в рабочей директории
   - `--hard`: обновляет HEAD, очищает index, восстанавливает файлы из коммита, удаляет файлы не из коммита

2. **revert** - отмена изменений коммита
   - Вычисляет обратный diff (что было добавлено → удалить, что было удалено → восстановить)
   - Применяет изменения к текущему состоянию
   - Создает новый коммит с сообщением "Revert \"<original>\""

3. **cherry-pick** - применение изменений из коммита
   - Вычисляет diff между коммитом и его parent
   - Применяет diff к текущему HEAD
   - Сохраняет файлы, которые не были изменены в коммите
   - Создает новый коммит с оригинальным сообщением

4. **merge** - слияние веток
   - Находит общий предок (merge base)
   - Определяет возможность fast-forward merge
   - Объединяет изменения из обеих веток
   - Обнаруживает конфликты и помечает их маркерами
   - Создает merge commit с множественными родителями

5. **move-to** - перемещение коммитов (rebase)
   - Находит общий предок между ветками
   - Последовательно применяет коммиты на новую базу
   - Перезаписывает историю ветки

### Разрешение хешей коммитов

**Файл:** `internal/commands/commit_utils.go`

Все команды, работающие с коммитами, поддерживают различные форматы указания коммита:

- **Полный хеш** (64 символа): `abc123...def789`
- **Короткий хеш** (8+ символов): `abc12345` - ищется по префиксу в истории всех веток
- **HEAD** - текущий HEAD коммит текущей ветки
- **HEAD~n** - n коммитов назад от HEAD (например, `HEAD~1` - предыдущий коммит)

Функция `resolveCommitHash()` обрабатывает все эти форматы и возвращает полный хеш коммита.

**Особенности:**
- Поддержка множественных родителей: при обходе истории учитываются все родители merge commit
- Короткие хеши ищутся по всем веткам для уникальности
- `HEAD~n` работает корректно с merge commits (следует по первому родителю)

### Хеширование

Все объекты идентифицируются по SHA-256 хешу:
- **Blob**: хеш от несжатого содержимого
- **Tree**: хеш от JSON представления
- **Commit**: хеш от JSON без поля hash

Формат хеша: 64 символа hex (SHA-256)

### Хранение объектов

Объекты хранятся в структуре:
```
objects/
└── <type>/sha256/
    └── <prefix>/<suffix>
```

Где:
- `<type>` - `blobs`, `trees`, или `commits`
- `<prefix>` - первые 2 символа хеша
- `<suffix>` - остальные 62 символа хеша

Пример: хеш `abc123...` → `objects/blobs/sha256/ab/c123...`

### Дедупликация

Forester автоматически дедуплицирует объекты:
- Если blob с таким хешем уже существует, он не сохраняется повторно
- Это экономит место при хранении одинаковых файлов в разных коммитах

### Сжатие

Blobs автоматически сжимаются перед сохранением:
- Используется zlib/deflate
- Сжатие прозрачно для пользователя
- При чтении blob автоматически распаковывается

- `commit` - создание коммита
- `switch` - переключение между ветками/коммитами
- `branch` - управление ветками
- `tag` - управление тегами

### Просмотр истории
- `log` - история коммитов
- `show` - детали коммита
- `diff` - различия между версиями
- `compare` - сравнение версий
- `reflog` - история изменений ссылок

### Работа с историей
- `reset` - откат к коммиту
- `revert` - отмена изменений коммита
- `cherry-pick` - применение коммита
- `merge` - слияние веток
- `move-to` - перемещение коммитов (rebase)

### Управление изменениями
- `stash` - временное сохранение изменений
- `clean` - удаление неотслеживаемых файлов

### Специализированные функции
- `lock` - блокировка файлов
- `review` - система review для 3D-контента
- `hook` - управление хуками
- `gc` - сборка мусора
- `rebuild` - сканирование object store (диагностика)
- `config` - управление конфигурацией
- `lol` - easter egg команда

## Совместимость с Git

Forester стремится к максимальной совместимости с Git:

- ✅ Git-like команды и опции
- ✅ Поддержка коротких хешей, HEAD, HEAD~n
- ✅ Merge commits с множественными родителями
- ✅ Обнаружение и разрешение конфликтов
- ✅ Fast-forward и merge commits
- ✅ Stash система
- ✅ Reflog для восстановления
- ✅ Hooks (pre-commit, post-commit, pre-checkout, post-checkout)
- ✅ Стратегии и опции merge
- ✅ Squash merge
- ✅ Rebase (через move-to)

**Отличия от Git:**
- Файловые метаданные в `.DFM/` (manifests, reviews, locks — специфичны для 3D workflow)
- Content-addressable storage с автоматическим сжатием
- Специализированные функции для 3D-контента (review, блокировки)
- Глобальная конфигурация в `~/.dfm/setup.cfg`
