# UX-исследование DFM-GUI 0.8.1

**Объект:** графический клиент Difference Machine (холст [DFM 0.8.1 component](https://www.figma.com/design/qlwKiMPZblz96VSM2F3DlS/DFM-for-Cursor?node-id=4191-5772), node `4191:5772`) и связанные спеки `.cursor/gui/`.  
**Дата:** 2026-09-02. **Метод:** экспертный разбор (эвристики Нильсена, IA, сценарии JTBD). Не пользовательский тест.  
**Ограничение:** оценка макета и спек, не живой сессии с художниками. Выводы — гипотезы для следующей итерации дизайна.

---

## Краткий вывод

DFM-GUI выглядит как **файловый менеджер для DCC-пайплайна**, а не как git-клиент. Это главная сильная сторона: сетка превью, история файла, визуальный diff картинок и merge объектов Blender совпадают с тем, как художник думает об ассетах.

Слабое место — **обучаемость и швы информационной архитектуры**. Буквенные бейджи без легенды, три разных композера коммита, вкладка Stash с копи «No files yet», клик по папке в тупик File Info Null и сжатый merge объектов в маленьком диалоге. Визуально продукт зрелый; по смыслу VCS для не-инженера ещё не доведён.

**Вердикт:** дизайн готов как визуальный канон 0.8.1. Перед расширением поверхности лучше закрыть 7–8 P1 по копи, терминологии и сценарию «первый коммит / первый merge».

## Дополнение 2026-09-03: Compare / Revert без родителя

Макеты diff обновлены. Канон: [Image](https://www.figma.com/design/qlwKiMPZblz96VSM2F3DlS/DFM-for-Cursor?node-id=4282-21006), [Text](https://www.figma.com/design/qlwKiMPZblz96VSM2F3DlS/DFM-for-Cursor?node-id=4290-22243), [Binary](https://www.figma.com/design/qlwKiMPZblz96VSM2F3DlS/DFM-for-Cursor?node-id=6067-13828).

Раньше на `Tab=4) No commits` / `type=2) No commits` шапка **прятала** Compare и Revert: нет родителя → нет 2-up → нет действий. Это ломало сценарий «я поправил файл после первого коммита и хочу вернуть как было».

**Решение.** Кнопки остаются на всех трёх kind, даже если истории сравнения нет.

| Состояние | Что на экране | Compare | Revert |
|-----------|----------------|---------|--------|
| Есть родитель | 2-up / Unified / binary stub | extract path → tmp_review | `restore.file` этой ревизии в workdir |
| Нет родителя (первый коммит) | одно изображение / плоский текст / тот же stub; табы disabled | то же: эта ревизия ↔ workdir | то же: откат workdir к **единственной** версии файла |

Ментальная модель для художника — не git parent, а **Ctrl+Z файла**: выбранная ревизия (пусть она корневая) — точка восстановления локальных правок. Подтверждение Revert по-прежнему через destructive dialog, не `window.confirm`. Не путать с `commit.revert` всего коммита.

Спеки: [commit-diff-image](./components/items/commit-diff-image.md), [commit-diff-text](./components/items/commit-diff-text.md), [commit-diff-binary](./components/items/commit-diff-binary.md), [file-history](./views/file-history.md), [commit](./views/commit.md).

**Что это закрывает.** Дыра контроля на History of File / View Commit, когда выбран корневой коммит: действия больше не исчезают вместе с Before-кадром.

**Что остаётся.** [File View — No History](./views/file-preview.md): path ещё ни разу не в VCS. Compare/Revert на diff item не из чего вызывать — нет blob ревизии. Кнопки живут в шапке **diff**, не в Current preview. Нулевой истории файла это не заменяет: «Ctrl+Z» требует хотя бы один коммит этого path.

## Для кого этот GUI

Продукт — VCS **Forester** + окно Wails + аддон Blender. GUI не заменяет Blender: он держит **рабочую копию проекта** (папки, `.blend`, текстуры, видео) и ревизии.

| Роль | Работа в GUI | Что должно быть очевидно |
|------|----------------|---------------------------|
| Художник / моделлер | Найти файл, увидеть что изменилось, сохранить версию, сравнить картинку | Сетка, превью, «грязный» файл, коммит без git-жаргона |
| TD / пайплайн | Ветки, stash, ignore, lock, GC, пути Blender | Настройки и destructive-действия с подтверждением |
| Супервайзер | История файла, состав коммита, merge объектов | Diff картинки, список файлов коммита, объекты MERGE/RENAME/DELETE |

Метафора конкурентов, с которыми пользователь сравнивает окно:

- Finder / Explorer — обзор папки (ожидание: клик выбирает, двойной клик открывает).
- GitHub Desktop / Fork — коммит и история (ожидание: один композер, одна история).
- Plastic / Perforce — lock и бинарные ассеты (ожидание: статус файла читается без легенды).

DFM ближе к Finder + GitHub Desktop, с уникальным слоем **объектов Blender**. Этот слой почти спрятан в диалог Merge — при том что это отличие продукта.

## Информационная архитектура

Окно 1429×768: **Header Window** (нативное меню ОС) + три колонки.

```text
Left 309          Center 788 | 1120           Right 332 | скрыта
History / Stash   сетка / превью / diff       File Info
Uncommitted       хлебные крошки, фильтры     или Null
ветки
```

Пять семейств экранов:

| Семейство | Когда | Left |
|-----------|--------|------|
| First Start | нет текущего репо | нет колонок (640×656) |
| Обзор папки | сетка workdir | Project view |
| Файл workdir | открыт один файл | File view (история **этого** path) |
| Ревизия файла | выбран коммит в истории файла | File view |
| Коммит проекта | выбран коммит в History | Project view, right нет |

Это сильная модель: один shell, контекст меняет колонки, а не «страницы приложения». Цена — **при открытии файла пропадает история проекта**. Художник, который шёл по коммитам слева, после двойного клика по `.blend` видит другую ленту. Возврат — маленький шеврон `<`.

Меню **File / Edit / Repository / Branches / Window** дублирует часть панельных действий (Open, Settings, Create repository). Для десктопа это правильно. Help в Header Settings — disabled, диалога нет.

## Сильные стороны

### 1. Метафора файлового менеджера, не git

Корень, подпапка, breadcrumb Home, сетка 48×48, двойной клик в папку — это язык художника. Default плотность как мелкие значки в Finder, а не крупные плитки галереи. Колонки сетки считаются от окна (`auto-fill` + `minmax(106px, 1fr)`), а не срисованы «7 колонок с кадра 1429». Это редкая для VCS-GUI честность к реальному окну.

### 2. Визуальный review как первоклассный сценарий

- File Info: превью 308×308 (Image / Text / Blend / Binary).
- File View: полный кадр картинки, текст, binary stub.
- Diff картинки: **2-up / Swipe / Overlay** — то, чего ждут от сравнения рендеров и скриншотов.
- Коммит проекта: список файлов + diff выбранного path на всю ширину (right скрыт).

Для пайплайна с `.blend` + текстурами это важнее split-diff кода.

### 3. История файла, не только история репозитория

Открытие файла меняет left на «History of this path» + Current preview. Художник думает «как менялась сцена», а не «какой hash на HEAD». Это близко к Plastic / Perforce file history и дальше от `git log`.

### 4. Empty и аварийные состояния спроектированы, а не забыты

На холсте есть отдельные кадры, не один generic empty:

| Кадр | Смысл |
|------|--------|
| Empty DFM Project | нет файлов, нет истории |
| Empty DFM Folder | файлы есть, `.DFM/` нет |
| Empty History | репо есть, коммитов нет |
| DFM Damaged | HEAD/object сломан, Verify |
| File Missing | файл исчез с диска, выбор не сбрасывается |
| File View — No History | превью живо, истории path нет |
| Stashes Null | пустой stash |
| Not Select A File | right пустой |

Damaged — **экран**, не toast. Missing file не выкидывает пользователя из File View. Это зрелая модель ошибок.

### 5. Атомарная система и паритет макет → код

Слои Atom / Item / Panel / View не смешиваются. Варианты `state` / `type` / `size` / `Lock`. Запрет выдумывать счётчики и подсказки. Для прототипа 0.8.1 это снижает визуальный шум и расхождение реализации.

### 6. Коммит без staging-ритуала

Нет git index как отдельной колонки. Есть **Uncommitted** и три входа: все файлы слева, выбранные справа. Для художника «сохранить версию» ближе, чем stage → commit. Карточка композера в панели, не модалка поверх сетки — контекст файлов остаётся.

### 7. Blender-специфика не имитация GitHub

Отдельные бейджи объектов (MERGE / RENAME / DELETE), превью Blend, Settings → External editors / Forester / путь Blender, lock на тайле. Merge — wizard «ветка → объекты». Это продуктный якорь, не обёртка над `git`.

### 8. Статус системы разведён по каналам

| Канал | Когда |
|-------|--------|
| Toast | мутации, Open/Init |
| Баннер | merge in progress, detached HEAD |
| Экран | Damaged |
| Бейдж | dirty / ignored / lock |

Не всё красится в красный Alert. Close баннера не abort merge — правильное разделение «спрятать UI» и «отменить VCS».

### 9. Нативное десктопное окно

Title bar ОС, menu bar (на macOS — системный), не кастомные traffic lights в webview. Title `Difference Machine ({name})` показывает репозиторий без открытия меню. First Start — отдельное маленькое окно, не пустой трёхколоночный shell.

### 10. Плотность и collapse

Правая колонка убирается, центр 1120. Зум сетки есть как поведение (Cmd+wheel), даже если аффорданса нет. Виртуализация и очередь превью заложены в спеки — GUI не обещает нарисовать тысячу thumbs сразу.

## Слабые стороны и находки

### P1 — ломают понимание

**P1-1. Бейджи A / M / N / D / R / i без легенды**  
Квадрат 20×20, одна буква. Для git-пользователя M/D привычны; для художника **N vs A** (untracked vs staged new) и строчная **i** — загадка. Lock — иконка, остальные — буквы: ещё один код. Фильтры знают статусы, а сетка — нет.  
*Рекомендация:* tooltip / строка легенды в Filters, или подпись при первом запуске. Не раздувать тайл.

**P1-2. Пустой Stash говорит «No files yet»**  
Кадр Stashes Null (`6035:12553`): центр как пустая папка, CTA **Create stash**, слева «No stashes yet». Stash — не папка с файлами. Копи с Empty DFM Project переиспользовано. Плюс: пустой stash **прячет сетку рабочей копии**. Пользователь переключил вкладку и «потерял проект».  
*Рекомендация:* другой empty (что такое stash, когда жать Create), сетку workdir не подменять Folder Empty — или явный заголовок, что это не файлы папки.

**P1-3. Клик по папке → File Info Null**  
Выбор папки подсвечивает тайл, справа «Select a file to view details». Метаданных папки нет (размер, число файлов, ignore). В Finder клик по папке хотя бы даёт превью/info. Здесь — тупик до выбора файла или двойного клика.  
*Рекомендация:* Folder Info (имя, путь, счётчики, ignore) или не держать right открытым на выборе папки (как Empty Project).

**P1-4. Три композера коммита**  
Create Commit (несколько файлов, форма **справа**), single file (справа в File Info), all files (форма **слева**, selection сброшен, слева Disable на Uncommitted в других вариантах). Правило «выбор файла не переносит форму» — защита от прыжка, но три ментальные модели. Disable левой карточки при коммите выбора выглядит как поломка.  
*Рекомендация:* один якорь формы (всегда справа или всегда в Uncommitted) + явное «N files». Сейчас это плата за точное следование трём кадрам.

**P1-5. Открытие файла подменяет историю проекта**  
Двойной клик → left = History of file. Лента коммитов проекта исчезает. Связь «этот файл в том коммите, который я смотрел» держится только в голове. Back — шеврон `<` в хедере файла, легко не заметить.  
*Рекомендация:* сохранить контекст (чип «из коммита …», или не размонтировать History, а стек/tabs). Усилить Back.

**P1-6. Merge объектов спрятан в узкий диалог**  
Дифференциатор продукта — объекты Blender с тегами MERGE/DELETE/RENAME. UI: 796×374, список файлов + «Objects not detected», без превью сцены. Художник мержит вслепую относительно вьюпорта Blender. Wizard Next не стартует merge (хорошо), но шаг view objects не объясняет *что произойдёт с мешем*.  
*Рекомендация:* крупнее превью / связь с аддоном («откроется Blender»), не только текстовый список.

**P1-7. Три «пустых» входа в репозиторий**  
First Start (Create / Open), Empty DFM Folder (файлы на диске, Create repository слева), Empty History (файлы + `.DFM/`, нет коммитов). Спека это различает, пользователь — нет: «почему слева Create, если сетка уже полная?». First Start подписан **Prototype 0.8.1** — снижает доверие.  
*Рекомендация:* одна формулировка «эта папка ещё не репозиторий» vs «репозиторий без версий». Убрать Prototype с героя или заменить на «Version 0.8.1».

### P2 — трение и дыры кадров

**P2-1. List View есть в атомах, нет в продукте**  
`Item / List View / File|Folder` нарисованы. 0.8.1 — только сетка. Для папок с сотнями `.png` / `.blend` список привычнее. Переключателя нет, спека запрещает.

**P2-2. Масштаб сетки без аффорданса**  
Cmd/Ctrl+wheel, диапазон 106…360, рестарт сбрасывает. В UI нет «zoom» — по правилу паритета. Пользователь не узнает, что крупные превью возможны, и может случайно зумить WebView, если модификатор не пойман.

**P2-3. «Only changed» меняет scope папки**  
Вкл. — сетка = dirty **всего проекта**, не текущая папка. Breadcrumb врёт: вы в `assets/chars`, видите файлы из `renders/`. Фильтр в popover, без чипа на хедере.

**P2-4. Нет History of File для binary**  
Есть Image и Text. Вопрос в `views/architecture.md` открыт. `.blend` часто binary stub — история файла обрывается как раз на главном типе ассета.

**P2-5. View Commit без выбранного path**  
Кадра нет. Спека: не выдумывать «select a file». Три примера сразу с выбранным файлом. Реализация должна выбрать first path молча — скрытое правило.

**P2-6. Compare уходит в ОС**  
`compare.extract` + `open: true` — файловый менеджер в `tmp_review`. Из визуального diff — прыжок в Finder. Обратного «сравнить в окне DFM» на кадре нет.

**P2-7. Help disabled, онбординга нет**  
После Create repository — сразу сетка или empty. Нет «сделайте первый коммит». Settings огромные (Profile, Appearance, Repositories, Editors, Forester, GC, Ignored) — TD найдёт, художник нет.

**P2-8. Клавиатура и a11y не специфицированы**  
Range/multi-select упомянуты. Фокус, стрелки по сетке, Esc из композера, typeahead — нет. Бейджи без текстовой легенды бьют и a11y.

**P2-9. Правая колонка по умолчанию пустая**  
Root Folder держит 332px «Select a file…» всегда. Collapse есть, но default — пустой столбец. На ноутбуке 1366 это дорого. Empty Project right честно прячет — Root Folder нет.

**P2-10. i18n в макете неровный**  
First Start: Language English / Русский, весь остальной chrome английский. На холсте «Оverlay» (кириллическая О), «Сommit all files» (кириллическая С). Риск: в русском UI останутся английские empty и наоборот.

**P2-11. Uncommitted 0/0/0**  
Карточка всегда на месте (хорошо для якоря). Три нуля без подписи осей на кадре Root Folder читаются как битая статистика, не как «чисто».

**P2-12. Settings: Tab=Tab5**  
На холсте безымянный таб в variant-set. В спеке это Appearance. Для агентов и передачи файла — ловушка.

### P3 — полировка холста

- `Histpry of File`, `Dirrectory`, `Null Rtepository`, `Content /  File list`.
- Кадр SubFolder всегда с заполненным File Info — нет «подпапка, ничего не выбрано».
- File View Text Expanded в Figma высотой 720 vs канон 768.
- History of File Image: left 333 / center 1096 vs канон 309 / 1120.
- Stages в именах слоёв vs Stash в UI.
- Нет Clone на First Start (осознанно) — для студии с сервером это дыра следующего релиза, не 0.8.1.

## Сценарии

Оценка: проходит / с трением / ломается на макете.

### Первый запуск → первый коммит

First Start ясный (Create / Open / язык). Дальше развилка: пустая папка, папка с файлами без `.DFM/`, init с файлами без коммитов. Три empty. Первого коммита на empty history нет как CTA в центре (CTA слева в Uncommitted / Create repository).  
**Трение.** Онбординг не ведёт за руку.

### Ежедневный обзор ассетов

Сетка, превью, бейджи, File Info, collapse — сильный сценарий. Поиск и фильтры в хедере папки. Слабо: легенда статусов, скрытый зум, Only changed, нет списка.  
**Проходит** для тех, кто уже понял буквы.

### Сохранить версию выбранных файлов

Правый композер, Disable слева. Сообщение + Create. Нет шаблонов сообщений, нет привязки к скриншоту сцены на кадре композера (в аддоне screenshot_path есть, в GUI-карточке — нет).  
**Трение** из-за трёх веток композера.

### Посмотреть, как менялась текстура

File View → клик коммита → 2-up / Swipe / Overlay. Лучший сценарий GUI. Корневой коммит: одно превью, табы disabled, **Compare / Revert остаются** (откат workdir).  
**Проходит.** Binary/blend-история как отдельный View — дыра (P2-4); stub + те же кнопки.

### Слить ветку с персонажем в `.blend`

Branches → Merge → Next → список файлов/объектов → Merge → wait (Blender background). Баннер in progress. Для TD приемлемо, для художника — чёрный ящик.  
**Трение / риск** на дифференциаторе продукта.

### Файл удалили снаружи / репозиторий сломан

Missing file и Damaged — отдельные кадры, Verify, Recover commit в меню.  
**Проходит** лучше типичного git GUI.

## Рекомендации (очередь для дизайна)

Не расширять поверхность (list view, clone, help center), пока не закрыты смысловые швы.

### Цикл A — копи и IA (высокий эффект, мало новых экранов)

1. Легенда статусов в Filters или sr-only + tooltip по спеке.
2. Переписать Stashes Null; не маскировать workdir под «No files yet».
3. Folder Info или скрывать right на выборе папки.
4. Title First Start: Version, не Prototype.
5. Чип «Only changed · entire project», когда фильтр шире текущей папки.
6. Унифицировать Stages → Stash на холсте; починить кириллические С/О.

### Цикл B — один коммит, один merge

7. Свести композеры к одному якорю; Disable Uncommitted не использовать как «режим».
8. Усилить Back и сохранить след проектной истории в File view.
9. Расширить Merge: превью / счётчик объектов / «продолжится в Blender».
10. Кадр History of File Binary (хотя бы stub, как View Commit Binary).
11. Кадр View Commit с пустым path (первый файл или явный empty).

### Цикл C — мощность без нового chrome

12. Решить: List View в 0.8.x или выпилить атомы с холста «продукта».
13. Аффорданс масштаба сетки (не подпись «N columns» — иконка или жест в хедере, если разрешите в макете).
14. Онбординг одного шага после init: «Create your first version».
15. Клавиатурная модель сетки (спека, не обязательно новый кадр).
16. Help: страница или disable снять.
